IronID On-device gym equipment recognition

Point a phone at any gym machine and know what it is in ~33 ms — no cloud, no privacy leak, no internet at all. 99.02% accuracy from a 5.72 MB model.

  • roleteam project
  • headline99.02% @ 5.72 MB · 30–35 ms
github ↗

the problem

Cloud vision in a gym is the wrong answer twice: every frame adds round-trip latency, and camera frames from a private space get shipped to external servers. The model had to run entirely on the phone.

But gym equipment is visually confusing — steel, cables, benches everywhere. A small model mixes them up; a big model won't fit a phone. The whole project lives inside that squeeze.

how it works

  1. Benchmark three mobile architectures

    On 10 equipment classes: MobileNetV3-Small (3.6 MB, 92%) — too weak. EfficientNet-B0 (15.5 MB, 99%) — too heavy. MobileNetV3-Large (11.5 MB, 97%) — the right starting point.

  2. Test knowledge distillation honestly

    EfficientNet-B0 as teacher for MobileNetV3-Small moved accuracy from 92% to just 93%. Structural capacity was the ceiling, not training — so distillation was dropped instead of forced.

  3. Prune, then quantize

    Magnitude-based pruning with polynomial sparsity decay (0% → 50% over 10 epochs), then TFLite conversion with Float16 quantization: 11.37 MB → 5.72 MB while accuracy rose to 99.02% — the pruning re-training actually improved generalization.

  4. Ship it like a product

    Kotlin + CameraX for live input, TFLite interpreter for inference, and a 60% confidence gate — below it, the app asks the user to reframe rather than guess wrong. A GPT-3.5-turbo coach builds routines; GitHub Actions runs CI/CD.
